문서 3 · AutoAgent
베팅실행모델파이프라인 역할라우팅·위험4축 자기평가 강점·빈틈
우리 하네스 · cross-model orchestrator

두 모델이 교대로 구현하고
서로를 리뷰한다

AutoAgent는 Claude Code CLI와 Codex CLI를 서브프로세스로 구동해, 별도의 타깃 워크스페이스를 두 모델이 교대로 구현·리뷰하게 조율한다. 비결정적 에이전트를 결정적 Python 제어 흐름으로 감싸고, 위험한 변경은 사람이 승인 게이트를 통과시켜야 코드가 바뀐다. 덱 두께 스펙트럼상 중간, 타깃 밖 외부·비침투.

Claude (기획·구현·리뷰·보고) Codex (검증·리뷰·평가·구현) 사람 (승인 게이트)

015개의 설계 베팅

01 크로스-모델 리뷰

리뷰어는 항상 구현자의 반대 모델. 같은 모델의 자기검토는 같은 맹점 공유 → 적대적 다양성.

02 코드가 조율, 프롬프트가 "무엇"

행동은 prompts/**/*.md, 오케스트레이션만 Python. Codex가 Claude 스킬을 못 읽어 stdin 중립채널에 행동을 둔다.

03 사람 승인 게이트

high-risk/db는 코드 변경 전 정지, --resume으로만 진행. "재개 실행 = 승인 행위".

04 외부·비침투

타깃 안 건드림, 상태는 하네스 레포에만, 자동 커밋 없음. 여러 프로젝트에 재사용.

05 결정적 제어 흐름

루프·분기·예산·게이트 전부 Python. 재현·감사 가능, "얼마나 도느냐"를 --max-agent-calls로 통제.

02실행 모델

서브프로세스는 타깃 프로젝트를 cwd로 실행된다. 이 하네스 레포는 편집 대상이 아니라 조율자다.

# run.py --workspace C:\...\TargetProject --request "..."
run.py
  └─ 서브프로세스로 claude.cmd / codex.cmd 호출
       ├─ cwd    = config.workspace   ← 타깃 프로젝트 (하네스 레포 아님!)
       ├─ stdin  = render_template(prompt.md, values)  ← "무엇을 할지"
       └─ stdout = runs/<stamp>/NN_*.md 로 캡처         ← 산출물

03routed 파이프라인 (주력)

색이 담당 모델 — Claude / Codex / 사람. 리뷰어는 항상 구현자의 반대 모델.

route_task ──► route.json
  │
  ▼ [preamble / 계획]
  context(claude) ──► architecture(claude) ⇄ validation(codex)   ← 검증 루프
  │
  ▼ 읽기전용 or docs/review? ── yes ──► docs 라우트(평가+보고, 코드변경 없음)
  │ no
  ▼ [승인 게이트] approval_required? ── yes ──► checkpoint + 정지, --resume 대기
  │ no
  ▼ git 베이스라인 확인 ── 유효 HEAD 없으면 구현 차단
  │
  ▼ [구현 라우트]
  impl(04) ──► review(05) ⇄ fix(06) ──► final-review(07) ──► eval(08) ──► report(09)

simple

plan → execute → review 최소 루프

routed

역할 기반 파이프라인(위). 주력.

decompose

대규모 요청 → task_graph.json. 구현 절대 안 함.

05라우팅 & 위험도

라우팅

--task-type 명시 시 키워드 분류 우회. auto면 명사 점수 → 최고점. 구현 의도 가드: 구현 동사가 있으면 docs 오분류를 backend/frontend로 교정.

위험도 두 층

①라우팅 risk_level(db_score→subtype=db/high, HIGH_RISK_TERMS→high) ②승인 게이트 is_high_risk(risk_level=="high" or subtype=="db" or HIGH_RISK_REQUEST_TERMS). frontend는 항상 medium.

알려진 잔여(토론거리): 두 고위험 리스트 중복 · frontend 게이트 공백 · 키워드 substring 취약(자기 코드 심볼이 오발 유발 — 라우팅·DB 게이트 모두 교정됨).

06프레임워크 4축 자기평가

축AutoAgent의 상태평
Contextrun 산출물 + checkpoint(핸드오프는 resume 한정). 상시 상태 외부화(worklog류) 약함★★
ToolMCP 거의 없음. 행동을 프롬프트 중립채널로(Codex가 Claude 스킬 못 읽음)★
Permission사람 승인 게이트(high-risk/db) + 권한모드 + codex 샌드박스 + git 베이스라인. 경로 격자가드 없음★★
Verification테스트 없음 → dry-run 바이트 패리티 + 크로스모델 상호 리뷰. 실행 테스트 게이트 없음★
Orchestration9역할 고정 파이프라인 + 예산 + stop-after. decompose 제한적 병렬 실행기(worktree, 라이브 미검증)★★

덱 패턴 대응: Plan→Execute ✅ · Generate↔Review(크로스모델) ✅ · Router ✅ · Human Approval ✅ · Parallel 제한적(미검증) · Verification Loop(실테스트 없음) ⚠️.

07안전·검증 & 강점·빈틈

안전 & 검증

--read-only · 유효 Git 베이스라인 없으면 구현 차단 · decompose 구현 안 함 · 자동 커밋·푸시 없음 · --max-agent-calls 예산 · --stop-after. 테스트 없음 → --dry-run 바이트 패리티. 도그푸딩: 크로스모델 리뷰가 실제 안전 회귀·설계 갭을 잡아냄.

프로젝트 레지스트리

--project <name> → projects/<name>/{config.json,runs}. 우선순위: per-project > global > env > default. 미지정 시 오늘과 100% 동일.

강점 (덱 렌즈)

① 크로스모델 적대 리뷰(자기평가 편향 대응) ② high-risk 사람 승인 게이트(Permission "승인" 구현) ③ 외부·비침투(재사용성) ④ high-risk opus/xhigh 승격 ⑤ 결정적 파이프라인 + resume 핸드오프

빈틈

① 실행 테스트 게이트 없음(dry-run·리뷰로 대체) ② 병렬은 제한적(decompose 실행기, 라이브 미검증) ③ 경로 격자가드·시크릿 차단 없음 ④ 상시 상태 외부화 약함 ⑤ MCP·도구층 미미 ⑥ 키워드 라우팅 취약

harness-test가 "가드레일·결정론 검증"으로 강하다면, AutoAgent는 "크로스모델 + 사람 승인 + 외부 분리"로 강하다. 덱의 이상형에서 Permission의 '승인 루프'와 자기평가 편향 대응을 정면 구현했고, Verification(테스트)·Tool이 비어 있고, 병렬은 제한적 구현(미검증)이다.
