가드레일을 먼저 깔고
그 안에서 자율 팬아웃

정책(policy.json v3) + 훅 강제 + 자율 JS 워크플로우 + 커맨드의 4층 하네스. 에이전트가 실수하지 못하도록 읽기도메인·쓰기범위를 정책으로 격자화하고, 모든 파일 접근을 사전 검사, 종료 시점에 테스트를 하드게이트한다. "한 작업 = 한 브랜치". 덱 기준 두꺼운 하네스, 앱 레포 안에 동거.

02프레임워크 4+1축 매핑

Context

CLAUDE.md + 에이전트 헤더 + docs/CODEMAPS(현황 진실원본) + ADR. progress 대신 .active-work.json(진행원장) + worklog/(Stop 자동기록) → 덱의 Ralph/Handoff를 거의 그대로 구현.

Tool

MCP 4종(sequential-thinking·arxiv·exa·github, 대개 로컬 off) + 스킬 7종(api-design·solid-principles 등, 에이전트 시작 전 체크리스트 주입).

Permission ★강점

policy.json 격자형 읽기(readBoundaries)/쓰기(write·deny) 경계 + guard-paths.py가 모든 Read/Write/Bash 사전검사 + 시크릿(.env·*.pem·*.key·.git) 전역차단. 단, 사람 승인 루프는 사실상 없음.

Verification ★강점

3중 결정론 게이트: 유닛(pytest/npm, Stop 하드차단·자동수정 3회) + 계약(schemathesis↔openapi) + 화면(Playwright+census). LLM 평가자 배제, exit code만 신뢰. e2e는 CI에서.

Orchestration

15에이전트·8워크플로우 결정론 팬아웃. "한 작업=한 브랜치"(ensure-branch.sh 멱등), 큰 작업은 planner가 세로 슬라이스 + roadmap 체크박스(수평 분할 방지). 리서치 층은 다중출처 + 적대반증 3렌즈 + confidence 등급.

04강점 & 빈틈

강점

① 정책 일원화(policy.json 단일원본) ② 격자형 경계 + 시크릿 차단 ③ 3중 결정론 검증(LLM 평가자 배제) ④ 무한루프 방지 다중장치 ⑤ 작업추적(active-work·worklog·ADR·codemap) ⑥ 리서치 다중검증(적대반증 3렌즈) ⑦ 자율 워크플로우 ↔ 상호작용 커맨드 분리

빈틈

① 크로스모델 없음(모델 정적 하드코드) ② 사람 승인 게이트 없음(도구·MCP 자동) ③ MCP 등록 시 전역접근 ④ 비용은 사후 worklog 집계(실시간 예산 아님) ⑤ 코드맵 수동유지(대규모 싱크 리스크)

본질 — "정책 → 훅 → 자율 워크플로우 → 커맨드"로 에이전트가 실수하지 못하게 가드레일을 먼저 깔고 자율 팬아웃. 적합: 중규모 팀 내 협업, 정책 준수 필수 조직.
