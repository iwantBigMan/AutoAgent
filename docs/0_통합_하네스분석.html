Part 1 · 요약

01프레임워크 덱 (이상형)

"AGENT = MODEL + HARNESS. 원시 LLM은 운영체제 없는 CPU. 좋은 답변은 모델이 일하는 환경에서 나온다."

4축 + 사다리

Context·Tool·Permission·Verification. Raw LLM → Subagent → Agent Team → Harness.

왜 실패하나

Context Degradation(1M 벤치 18.5% vs 76%) + Self-Eval Bias → 외부 Evaluator. Solo 20분/$9 vs Full 6h/$200.

패턴 · 두께

GAN·3-agent·Ralph·Permission·Tool P1~P6. 얇음(Claude SDK)→두꺼움(LangGraph). "두께=위험·반복·실패비용의 함수".

→ 전체: 문서 1 · 프레임워크 덱

Part 2 · 요약

02harness-test (동료 하네스)

"정책(policy.json) + 훅 강제 + 자율 워크플로우 + 커맨드 4층. 가드레일을 먼저 깔고 자율 팬아웃. 한 작업=한 브랜치."

Permission ★★★

policy 격자형 경계 + guard-paths 사전검사 + 시크릿 차단. (승인 루프는 없음)

Verification ★★★

3중 결정론 게이트(유닛·계약 schemathesis·화면 Playwright). LLM 평가자 배제, exit code만.

Orchestration ★★★

15에이전트·8워크플로우·루프가드(MAX_ROUNDS+무진전감지+예산+회귀금지).

빈틈: 크로스모델 없음 · 승인 게이트 없음 · MCP 전역접근. → 전체: 문서 2 · harness-test

Part 3 · 요약

03AutoAgent (우리 하네스)

"Claude·Codex를 서브프로세스로 구동해 별도 타깃을 두 모델이 교대로 구현·리뷰. 위험 변경은 사람 승인 게이트를 통과해야."

크로스모델 ★

리뷰어는 항상 구현자의 반대 모델. 덱의 "자기평가 편향"에 대한 정면 대응.

Permission ★★

사람 승인 게이트(high-risk/db) + 권한모드 + 샌드박스 + git 베이스라인.

외부·비침투

타깃 밖 오케스트레이터, 자동 커밋 없음, high-risk opus/xhigh 승격.

빈틈: 실행 테스트 없음(dry-run·리뷰로 대체) · 병렬은 제한적(decompose 실행기, 미검증) · 경로 격자가드 없음. → 전체: 문서 3 · AutoAgent

043자 비교 (프레임워크 렌즈)

정확성 주의: harness-test 조사 서브에이전트가 AutoAgent 기능을 일부 부풀렸다(자동 순서도 생성·실시간 토큰 모니터링·에이전트별 MCP 능력정의는 AutoAgent에 없음). 아래는 실제 코드 기준 교정본.

4축 성숙도

축프레임워크 이상형harness-testAutoAgent
Context목표문서+지도+메모리+핸드오프★★★ CODEMAPS·worklog·ADR★★ run 산출물·checkpoint
Tool최소·고임팩트·설명★★ MCP 4 + 스킬 7★ MCP 거의 없음
Permission허용/승인/금지 + 경계★★★ 경로가드+시크릿차단 (승인 약함)★★ 사람 승인 게이트+권한모드
Verification계산적 테스트 + Evaluator★★★ 3중 결정론 게이트★ dry-run + 크로스모델 리뷰
Orchestration역할 분업 + 루프★★★ 15에이전트·루프가드★★ 9역할 고정 + 예산
핵심 그림: harness-test는 Verification·Permission(가드레일)에서 앞서고, AutoAgent는 Permission의 "승인 루프"와 크로스모델 검증에서 앞선다. 둘은 서로의 빈틈을 메운다.

Part 4 · 핵심

05토론 포인트

  1. 검증 vs 승인 — 3중 결정론 게이트 vs 사람 승인 게이트, 무엇이 먼저? 둘을 합치면?
  2. 크로스모델의 값어치 — 두 모델 교차 비용 대비, 결정론 테스트로 품질 잡는 편이 싸지 않나?
  3. 하네스 두께 — 우리 도메인은 harness-test급 두꺼움인가, AutoAgent의 중간인가?
  4. 침투 vs 분리 — 앱 안 vs 외부 오케스트레이터, 재사용성 vs 밀착 자동화.
  5. 비계 걷어내기 — 덱의 건강성 체크를 적용하면 어디가 과설계인가?
